Price only the models a table names in `createPricing` (`/cost`): a table or override key prices its own id, that id followed by a date (`-20250929`, `-2025-08-07`, `@20250929`), and either after a `<provider>/` prefix, regardless of case. An id the table lacks no longer takes the price of another model whose key it contains (`gpt-5.7` was priced as `gpt-5`, `o1-mini` as `o1`, `gpt-5.4-chat-latest` as `chat-latest`); it has no price. Family aliases such as `opus` go in `fallback`, which still prices an id that no table key matches by the longest alias it contains. An override is keyed by a model, matched as a table key is, or by a `fallback` alias, which reprices the ids that take that alias but no longer a model the table names (`{ opus: … }` no longer reprices a tabled `claude-opus-4-8`). A partial override now takes the prices it lacks from the id's own price rather than from its key's entry, so `{ "gpt-4o": { input: 1 } }` keeps `gpt-4o-2024-05-13`'s output price.
