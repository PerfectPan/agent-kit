## Packages

`@rivus/agent-kit` connects to one Agent at a time. It is a universal Agent toolkit: it knows each Agent's id and home directory, lists its sessions, and reads their logs into one transcript model with one usage convention. Claude Code, Codex and Grok are today's built-in Agents, along with the others on [Supported Agents](/docs/agents).

`@rivus/agent-kit-collab` coordinates many Agents. It adds fenced leases (`/lease`), a single-instance process lock (`/process-lock`) and keyed scheduling lanes (`/lanes`). The package knows no particular Agent. Collab's entries use agent-kit's public platform and follow the same lockstep release.

Files, processes and the environment come from a `Platform` object that the caller passes in, so the reading code also runs in a browser. ACP is implemented in `/acp`. `/harness` installs an application's hooks and skills into these Agents and removes them again, with a ledger of what it wrote.

Status is 0.x. A minor release may contain breaking changes. Both packages share one lockstep release policy, so they ship the same version.

`builtinProviders` from `/providers` exposes each Agent's `identity`, `discovery`, `install`, `sessions`, `usage` and `acp` services when supported. Select a descriptor by `id`, then check the optional service before use. The ordinary entries share these service objects. Hook commands keep using `builtinHookDialects` from `/harness/events`, whose isolated build imports nothing and owns separate hook objects. `/catalog` retains `AgentKitError` and `isAgentKitError` so callers can recognize errors from shell functions.

The **Runs in** column marks entries that need `effect` with "with `effect`". Plain entries do not load that optional peer.
