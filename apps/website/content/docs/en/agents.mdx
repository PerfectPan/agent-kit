## Capability columns

The capability columns are the built-in provider objects: a service field that is present counts as supported. They are not typed by hand. Id, aliases and the home override are the Agents table from the package README.

## README wording

The README's support table uses these words where a cell is not "yes":

- Cursor sessions: session storage has no supported reader.
- Cursor usage: usage storage has no supported decoder.
- Cursor ACP: no supported ACP transport.
- Gemini CLI sessions: session storage has no supported reader.
- opencode sessions: session storage has no supported reader.
- Pi sessions: session storage has no supported reader.
- Pi ACP: no supported ACP transport.

## Homes and names

Every Agent in the table has a hook dialect in `/harness/events`.

`/acp` has a launch profile for Claude Code (`claude-agent-acp`), Codex (`codex-acp`), Gemini CLI, Grok and opencode. A profile's `warnings` name the facts not yet checked against the Agent.

`/transcript/usage` reads the usage of every Agent in the table except Cursor.

`builtinProviders` has an identity for each of them, and a home rule for each one except Cursor. Cursor's home cell is `none`: `CURSOR_CONFIG_DIR`, `$XDG_CONFIG_HOME/cursor`, `~/.cursor`. Discovery says `CURSOR_CONFIG_DIR` and `XDG_CONFIG_HOME` remain unsupported. See [Agent detection](/docs/connection/discovery).

Codex's default home includes archived sessions. `GEMINI_CLI_HOME` replaces the user's home. `PI_CODING_AGENT_DIR` expands `~`. opencode's home in this table is the data home (`$XDG_DATA_HOME/opencode`, otherwise `~/.local/share/opencode`), not the plugin/config home.

To display an Agent name, find `builtinProviders.find((provider) => provider.id === id)?.identity?.displayName`. Adding a provider is [Providers](/docs/concepts/providers).
