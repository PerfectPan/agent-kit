## README 用语

README 的支持表在单元格不是「是」时使用这些说法：

- Cursor 的会话：会话存储没有受支持的读取器。
- Cursor 的用量：用量存储没有受支持的解码器。
- Cursor 的 ACP：没有受支持的 ACP 传输。
- Gemini CLI 的会话：会话存储没有受支持的读取器。
- opencode 的会话：会话存储没有受支持的读取器。
- Pi 的会话：会话存储没有受支持的读取器。
- Pi 的 ACP：没有受支持的 ACP 传输。

## 主目录与名称

表里的每个 Agent 在 `/harness/events` 里都有 hook 方言。

`/acp` 为 Claude Code（`claude-agent-acp`）、Codex（`codex-acp`）、Gemini CLI、Grok 和 opencode 提供启动配置。配置的 `warnings` 列出尚未对照该 Agent 核对过的事实。

`/transcript/usage` 读取表里除 Cursor 以外每个 Agent 的用量。

`builtinProviders` 为表里的每个 Agent 提供 identity。除 Cursor 外，每个 Agent 还有主目录规则。Cursor 的主目录单元格是 `none`：`CURSOR_CONFIG_DIR`、`$XDG_CONFIG_HOME/cursor`、`~/.cursor`。发现说明 `CURSOR_CONFIG_DIR` 和 `XDG_CONFIG_HOME` 仍然不受支持。见 [Agent 检测](/docs/connection/discovery)。

Codex 的默认主目录包含已归档会话。`GEMINI_CLI_HOME` 替换的是用户主目录。`PI_CODING_AGENT_DIR` 会展开 `~`。表里 opencode 的主目录是数据目录（`$XDG_DATA_HOME/opencode`，否则是 `~/.local/share/opencode`），不是插件目录，也不是配置目录。

显示 Agent 名称时，查找 `builtinProviders.find((provider) => provider.id === id)?.identity?.displayName`。添加 provider 见 [Provider](/docs/concepts/providers)。
