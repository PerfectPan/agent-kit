能力列来自内置 Provider 对象：存在的服务字段计为支持。它们不是手写的。id、别名和主目录覆盖来自包 README 的 Agent 表。

<AgentSupportTable />

README 的支持表在单元格不是「是」时使用这些说法：

- Cursor 的会话：会话存储没有受支持的读取器。
- Cursor 的用量：用量存储没有受支持的解码器。
- Cursor 的 ACP：没有受支持的 ACP 传输。
- Gemini CLI 的会话：会话存储没有受支持的读取器。
- opencode 的会话：会话存储没有受支持的读取器。
- Pi 的会话：会话存储没有受支持的读取器。
- Pi 的 ACP：没有受支持的 ACP 传输。

表中的每个 Agent 在 `/harness/events` 里都有 hook 方言。

`/acp` 为 Claude Code（`claude-agent-acp`）、Codex（`codex-acp`）、Gemini CLI、Grok 和 opencode 提供启动配置。配置的 `warnings` 标出尚未对照该 Agent 核对的事实。

`/transcript/usage` 读取表中除 Cursor 以外每个 Agent 的用量。

`builtinProviders` 为其中每一个都有 identity，并且除 Cursor 外每一个都有主目录规则。Cursor 的主目录单元格是 `none`：`CURSOR_CONFIG_DIR`、`$XDG_CONFIG_HOME/cursor`、`~/.cursor`。发现说明 `CURSOR_CONFIG_DIR` 和 `XDG_CONFIG_HOME` 仍然不受支持。见 [Agent 检测](/zh/docs/connection/discovery)。

Codex 的默认主目录包含已归档会话。`GEMINI_CLI_HOME` 替换用户的主目录。`PI_CODING_AGENT_DIR` 展开 `~`。这张表里 opencode 的主目录是数据主目录（`$XDG_DATA_HOME/opencode`，否则是 `~/.local/share/opencode`），不是插件或配置主目录。

要显示 Agent 名称，查找 `builtinProviders.find((provider) => provider.id === id)?.identity?.displayName`。添加 Provider 见 [Provider](/zh/docs/concepts/providers)。
