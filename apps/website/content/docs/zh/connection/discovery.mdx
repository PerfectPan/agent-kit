---
title: Agent 检测
description: detectAgents 报告 runnable、found、missing 或 unknown，并附证据与登录状态。
---

`@rivus/agent-kit/discovery` 导出 `detectAgents`、`versionFromOutput` 和 `ProbeRecipe`。它可以在任何环境运行，需要平台。

`detectAgents(platform)` 对 [Agent 表](/zh/docs/agents) 中的七个 Agent 分别报告它是 `runnable`、`found`、`missing` 还是 `unknown`，并附上证据、命令打印的版本和登录状态。

默认情况下，登录状态只来自凭据文件和环境变量，不运行任何东西，也不返回密钥值。`authProbe: "commands"` 还会运行 Agent 自己的状态命令，每条配方列出这些命令的副作用。

版本探测默认运行，并使 Agent 成为 `runnable`。`versionProbe: false` 则什么都不运行。只有成功的版本探测才能确立 `runnable`。

命令不经 shell 运行，并带有时间限制。失败的检查记在 `problems` 里。`detectAgents` 解析为 `Installation[]`。探测失败记在该 Agent 的 `problems` 里。

`builtinProviders` 为其中每一个都有 identity，并且除 Cursor 外每一个都有主目录规则。

## 什么算作 found

`detectAgents` 根据 PATH 上的命令、应用程序路径，或 Agent 自己拥有的状态路径，报告 `found`。

配置证据使用已有的 `config` 种类。它的路径是会话存储、应用状态或凭据文件，不是任意配置。空存储仍然算数，保留下来的状态可以在命令被移除后仍确立 `found`。

安装器可以创建 Agent 主目录，并放入 hook、设置、MCP 服务器、skill、插件或扩展，而不安装这个 Agent。这些路径都不能确立 `found`。内置的 `mcpConfigPaths` 是空的，因为先前列出的 MCP 文件是共享的、安装器可写的配置。特别是 `~/.claude.json` 可以包含 MCP 配置：当已有其他证据时，它仍是登录状态的来源，但仅凭它存在并不能作为安装证据。认证变量也不能确立安装。

配置证据来自 Agent 自己拥有的会话存储、应用状态或凭据文件。Agent 主目录以及共享的 hook/MCP 设置、插件、扩展和 skill 不算数：只安装 hook 会让 Agent 保持 `missing`。

下表列出每一条内置配置证据路径。Agent 主目录路径使用 catalog 规则。覆盖会替换默认主目录，而不是两边都探测。会话和用量夹具只校验布局，不读取任何本机 Agent 数据。凭据路径来自已有的登录探测。发现只返回非机密的认证事实。

## 不算证据的路径

Harness 产物和共享配置仍然排除在外：

| Agent       | 排除在证据之外的路径                                                                           | 来源                                                                                                    |
| ----------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Claude Code | `skills/`、`settings.json`                                                                     | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/claude-code/src/install.ts) |
| Codex       | `plugins/`、`config.toml`、`hooks.json`、共享 skill                                            | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/codex/src/install.ts)       |
| Gemini CLI  | `extensions/`、`settings.json`                                                                 | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/gemini-cli/src/install.ts)  |
| Grok        | `hooks/`                                                                                       | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/grok/src/install.ts)        |
| opencode    | `$XDG_CONFIG_HOME/opencode/plugins/`（默认 `~/.config/opencode/plugins/`）、`opencode.json(c)` | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/opencode/src/install.ts)    |
| Pi          | `extensions/`、`settings.json`                                                                 | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/pi/src/install.ts)          |
| Cursor      | `~/.cursor/`、`~/.cursor/plugins/local/`、三个桌面根的 `User/mcp.json`                         | [策略](https://github.com/PerfectPan/agent-kit/blob/main/packages/providers/cursor/src/install.ts)      |

改变这些事实会影响使用内置配方的 `detectAgents` 消费者，包括 agent-presence，以及应用的安装与检测界面。没有命令、可识别的应用程序或 Agent 自己拥有的状态的机器，现在报告 `missing`。这包括只有 `~/.claude.json` 的 Claude Code（macOS 钥匙串登录、还没有会话），以及只被 hook 或 MCP 设置填满的机器。没有 CLI 时，Cursor 的桌面状态仍然可以确立 `found`。命令与应用程序路径检测、自定义配方，以及证据和状态接口保持不变。

要定制内置配方，选出它的 `discovery` 服务并传入 `providers`。见 [Provider](/zh/docs/concepts/providers)。用 `/testing` 的 `probeRecipeConformance` 检查自己写的配方。
