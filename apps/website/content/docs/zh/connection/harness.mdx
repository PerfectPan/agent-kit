title: Harness 安装
description: planInstall 与 applyInstall 写入 hook 和 skill，并记入账本。

`/harness` 把应用想要的内容装进 Agent（目前是 hook 和 skill），也可以再卸掉。它可以在任何环境运行，需要 `effect` 和平台。

导出：`planInstall`、`applyInstall`、`verify`、`uninstall`、`inventory`、`doctor`、`HarnessLive` 及其端口。

它先做计划，只在计划被应用时才改 Agent 目标。`InstallPlan` 是无法构造、也无法序列化的句柄。`applyInstall` 只接受 `planInstall` 返回的计划，否则以 `code` 为 `"unknown-plan"` 的 `AgentKitError` 终止，因此重启后要重新计划。持有 SQLite 锁期间，每一次目标变更都记入 `$XDG_STATE_HOME/agent-kit/harness` 下的账本，因此崩溃靠探测恢复，而不是重放。

```ts title="planInstall 与 applyInstall"
import { applyInstall, HarnessLive, planInstall, uninstall } from "@rivus/agent-kit/harness";
import { NodePlatformLive } from "@rivus/agent-kit/node/effect";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

const bundle = {
  owner: "my-app",
  version: "1.2.0",
  digest: "…",
  // `{agent}` becomes each agent's id; keep the command stable, agents that review hooks ask again when it changes.
  artifacts: [
    {
      type: "hooks",
      command: "/usr/local/bin/my-app-hook {agent}",
      events: { "claude-code": ["Stop"], codex: ["Stop"] }
    }
  ],
  legacyMarkers: ["my-app hook"] // what older versions registered without a ledger is replaced, not duplicated
} as const;

const program = Effect.gen(function* () {
  const plan = yield* planInstall(bundle, { agents: ["claude-code", "codex"] });
  // plan.changes: each file's text before and after; plan.commands; plan.expectedTrustPrompts; plan.notes;
  // plan.droppedHooks. A PlanConflict names, per conflict, the choices that resolve it ("force", "adopt", "backup").
  return yield* applyInstall(plan);
});
await Effect.runPromiseExit(program.pipe(Effect.provide(HarnessLive.pipe(Layer.provideMerge(NodePlatformLive)))));
// Later: uninstall("my-app") removes only what the ledger records and keeps files the user changed.
```

## 每个 Agent 写到哪里

- Claude Code 得到一个 skills 目录插件。
- Codex 得到一个插件（通过 `codex plugin`；当 `codex` 不在 `PATH` 上时，通过 `config.toml` 的 hook 组）。
- Gemini CLI 得到一个扩展。
- Grok 在 `~/.grok/hooks` 里得到一个文件。
- Cursor 得到一个本地插件。
- opencode 和 Pi 得到一座桥，把它们的事件转发给命令。

方言读作结束某事的事件（阶段 `finish`）同步送达。这些事件是 opencode 的 `session.idle`、`session.error`、`session.deleted`，以及空闲时的 `session.status`，还有 Pi 的 `agent_end`、`agent_settled` 和 `session_shutdown`。桥把它们交给命令，并等待它退出，最多 5 秒，因此结束事件会在下一个事件转发之前到达命令。

发送失败或超时仍然不会向 Agent 抛出，其他事件转发时不等待。超时会杀掉桥启动的 shell，因此更长的结束 hook 会被截断。同一拍里刚好在结束之前转发的活动事件，仍可能在结束之后到达命令。

## opencode 桥

opencode 桥按 opencode 发出的样子转发每条总线事件，并加上插件的 `directory`。工具 hook 则是 `{ type, properties, directory }`。

当 `file.edited` 这类事件没有指名会话时，桥加上 `currentSessionId`：该插件实例见过的、最近一条指名了会话的事件所属的会话，不论那条事件有没有被转发，直到该会话被删除。一个目录里有多个会话时，这是最近的那一个。

读取过程中抛出的载荷不会拒绝插件回调。`readHookEvent` 在 opencode 自己的会话路径之后读取 `currentSessionId`，因此指名了会话的事件保留那个 id。

即使 Agent 也会运行 Claude Code 的设置 hook，一条事件也只触发一次。

## 文件、崩溃与检查

共享文件保留它们的注释和格式。不通过符号链接写入，也不写入 chezmoi 管理的文件。不取得账本锁的工具所做的并发编辑可能丢失，且不留痕迹。

计划句柄不能序列化后交给后来的进程应用。重启之后，或遇到 `PlanStale`、`TargetChanged` 之后，要重新计划。

计划过程可能在账本锁下了结先前持有者尚未完成的操作。`verify` 可能确认一份落后于磁盘的账本。`doctor` 的锁检查可能在 harness 状态目录里创建锁文件。这些都不会改写 Agent 目标。

`uninstall("my-app")` 只移除账本记录的内容，并保留用户改过的文件。

Hook 载荷本身用 [Hook 事件](/zh/docs/connection/hook-events) 读取。安装创建的路径不是发现证据。见 [Agent 检测](/zh/docs/connection/discovery)。
