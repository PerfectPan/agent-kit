## 价格表

`/cost` 按调用方传入的价格表给用量记录计价，单位是每百万 Token 的美元价格。价格表可以是你自己的，也可以是 [`/cost/prices`](#价格快照) 提供的 LiteLLM 快照。它是纯计算，不导入任何模块，任何环境都可以运行。

导出：`createPricing`、`summarize`、`priceRecord`、`Pricing`。

```ts title="createPricing 与 summarize"
import { createPricing, priceRecord, summarize } from "@rivus/agent-kit/cost";
import { createNodePlatform } from "@rivus/agent-kit/node";
import { isUsageRecord, scanUsage, type UsageRecord } from "@rivus/agent-kit/transcript/usage";

const pricing = createPricing(
  { "claude-opus-4-8": { input: 5, output: 25, cacheRead: 0.5, cacheWrite: 6.25, cacheWrite1h: 10 } },
  { fallback: { opus: { input: 15, output: 75, cacheRead: 1.5, cacheWrite: 18.75 } } }
);
const start = new Date();
start.setHours(0, 0, 0, 0);
start.setDate(start.getDate() - 6);
const week = { since: start.getTime(), until: Date.now() };
const records: UsageRecord[] = [];
for await (const item of scanUsage(createNodePlatform(), week)) {
  if (isUsageRecord(item)) {
    records.push(item);
  }
}
const { total, groups } = summarize(records, pricing, { window: week, groupBy: ["agent"] });
```

## 如何计价

记录里已有 Agent 记下的金额时，`summarize` 直接使用该金额（Pi、opencode、Grok）。否则按模型价格给每一项计数计价，计数包括不含缓存的输入、缓存读取、5 分钟缓存写入、1 小时缓存写入和输出，再乘以记录的 `pricingMultiplier`。Codex 的优先层级为 2。

## 模型如何匹配价格

键的匹配不区分大小写。

- **价格表的键**各自只对应一个模型。一个键可以匹配这个 id 本身、id 加日期后缀（`-20250929`、`-2025-08-07`，或 Vertex AI 的 `@20250929`），以及它们加一个 `<provider>/` 前缀的形式。因此 `claude-sonnet-4-5` 可以给 `claude-sonnet-4-5-20250929` 和 `anthropic/claude-sonnet-4-5` 计价。其他后缀都视为另一个模型，所以 `gpt-5` 既不匹配 `gpt-5.7`，也不匹配 `gpt-5-codex`。
- **`fallback`** 存放系列别名，例如 `opus`：没有任何键匹配的 id，使用它所包含的最长别名。
- **`overrides`** 是你自己的规则。与价格表的键不同，它按子串匹配：id 使用它所包含的最长 override 键，该 override 覆盖价格表和 fallback 的价格，可以只覆盖一部分。因此 `{ opus: … }` 会同时改动 `claude-opus-4-8` 和 `claude-3-opus` 的价格，`{ "gpt-4o": … }` 也会作用到 `gpt-4o-mini`。

只覆盖部分价格的 override，缺少的价格取自这个 id 在不加 override 时的价格。以快照为例，`{ "gpt-4o": { input: 1 } }` 给 `gpt-4o-2024-05-13` 计价时，输出价格用它自己的 15 美元，而不是 `gpt-4o` 的 10 美元；本身没有价格的 id 仍然不计价。

## 没有价格时

没有价格的模型没有费用，结果是 `undefined`，不是 0。汇总中没有任何一项被计价时，`costUsd` 缺失。按模型拆开的 Grok 回合，按模型分别计价和分组。

记录来自 [Token 用量](/docs/connection/token-usage)。日志里有 Agent 自己记下的费用时，记录带 `costUsd` 和 `costSource: "agent"`；Codex 的优先层级还带 `pricingMultiplier`。

## 逐条计价

`priceRecord(record, pricing): PricedRecord` 按同样的规则给单条记录计价，适合需要自行分桶（例如按小时汇总）的宿主。

- 返回 `{ parts }`：记录按模型拆分（`usageByModel`）时，每个模型一个 part；否则整条记录一个 part。
- 每个 part 包含 `model`（记录没有模型名时缺失）、`usage`、计数时的 `modelCalls`，以及 `cost`：`{ costUsd, costSource }`。Agent 记下的金额，`costSource` 为 `"agent"`；按价格表算出的金额为 `"pricing-table"`。
- 无法计价的 part 没有 `cost`，这不等于费用为 0。把各 part 的费用按 Agent 和模型相加，就是 `summarize` 的分组结果。
- 拆分后的 part 只带它所属模型那一份的 `modelCalls`，不带整条记录的值；那一份没有计数时，part 就没有 `modelCalls`，所以各 part 加起来可能少于 `record.modelCalls`。按记录统计调用次数的宿主应读取 `record.modelCalls`，自行决定如何分给各模型。

```ts title="priceRecord"
for (const record of records) {
  for (const { model, usage, modelCalls, cost } of priceRecord(record, pricing).parts) {
    // Add usage, modelCalls and cost?.costUsd to the bucket of (the hour of record.timestamp, record.agent, model).
  }
  // The parts' modelCalls can add up to less than record.modelCalls, which a host counting calls per record reads.
}
```

## 价格快照

`/cost/prices` 是工具包内置的 LiteLLM [模型价格表](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json)快照，覆盖内置 Agent 会记录的模型。`litellmPrices` 是可以直接传给 `createPricing` 的价格表。`litellmPricesVersion` 的格式是 `<日期>+<commit>`，表示生成快照时所用的 LiteLLM 文件的日期（UTC）和 commit。把它和算出的费用一起保存，就能知道费用是按哪一版价格表算的。这个入口不导入任何模块，并且与 `/cost` 分开，自带价格表的宿主不会加载它。

```ts title="使用价格快照"
import { createPricing, summarize } from "@rivus/agent-kit/cost";
import { litellmPrices, litellmPricesVersion } from "@rivus/agent-kit/cost/prices";

const pricing = createPricing(litellmPrices);
const { total } = summarize(records, pricing);
// Keep { costUsd: total.costUsd, pricedWith: litellmPricesVersion } together.
```

快照只保留 Agent 直接调用其 API 的那些服务商的对话模型：Anthropic、OpenAI、Google Gemini、xAI、DeepSeek、Z.ai、Moonshot 和 MiniMax。键使用 LiteLLM 的模型名，并去掉服务商自己的前缀（写作 `grok-4.20`，而不是 `xai/grok-4.20`），因为 Agent 记录的就是不带前缀的名字；经由云平台和网关转发的同一批模型（`bedrock/…`、`vertex_ai/…`、`openrouter/…`）不收录。每个条目包含 LiteLLM 列出的输入、输出、缓存写入、1 小时缓存写入和缓存读取价格。每周一，一个 workflow 会在快照收录的价格发生变化时发起 PR，变化随下一次发布生效。

每个键只对应一个模型，所以快照里没有对应键的 id 就没有价格，不会借用其他模型的价格：在快照收录 `gpt-5.7` 之前，它不计价，也不会按 `gpt-5` 计价。想给这类 id 估价的宿主，可以在 `fallback` 里传入系列别名和自定的价格，或者用 `overrides` 直接给这些 id 定价。override 仍然按子串匹配，因为它由宿主自己编写：键为 `gpt-5` 的完整 override 会给 `gpt-5.7` 计价，并改动快照中所有 id 含 `gpt-5` 的模型的价格；只覆盖部分价格的 override 会改动这些模型，但 `gpt-5.7` 本身没有价格可补，仍然不计价。
