---
title: 租约
description: 每个任务一个所有者，围栏令牌永不回退。
---

`@rivus/agent-kit-collab/lease` 导出 `createLeaseManager`、`LeaseRepository`、`sqliteLeaseRepository`、`fileLeaseRepository` 和 `memoryLeaseRepository`。它是 Effect 入口，需要平台。它需要 [安装](/zh/docs/installation) 中那个 peer 版本的 `effect`。

租约让一次只有一个进程拥有一个任务，并拒绝过期所有者的写入。这个包不认识任何具体 Agent。

```ts title="createLeaseManager"
import { NodePlatformLive } from "@rivus/agent-kit/node/effect";
import { createLeaseManager, sqliteLeaseRepository } from "@rivus/agent-kit-collab/lease";
import { Effect, Layer } from "effect";

const LeaseLive = sqliteLeaseRepository({ path: "/var/lib/my-app/leases.db" }).pipe(
  Layer.provideMerge(NodePlatformLive)
);

const program = Effect.scoped(
  Effect.gen(function* () {
    const leases = yield* createLeaseManager({ ttlMs: 60_000, heartbeatMs: 15_000 });
    const lease = yield* leases.acquire("task:42"); // fails with LeaseHeld while another live holder renews it
    // Writes carry the fencing token; when the lease is lost, the fenced work is interrupted.
    yield* lease.runFenced((token) => saveResult(token));
    // Stop other work on loss by racing it against lease.lost.
    yield* longRunningWork.pipe(Effect.raceFirst(lease.lost));
  })
);

await Effect.runPromiseExit(program.pipe(Effect.provide(LeaseLive)));
```

- 一份租约有一个持有者。它的代次，也就是围栏令牌，每次取得都增长，永不回退。释放把记录留作墓碑。失去租约后再取得会得到新的代次，因此旧句柄的令牌被拒绝。
- 持有者在取得它的 Scope 里每 `heartbeatMs` 续约一次。`heartbeatMs × 2` 不得超过 `ttlMs`。关闭 Scope 会停止心跳并释放租约。
- 同一台主机上进程已经消失的持有者（或其 pid 现在属于另一个进程）会立刻被接管。还活着但停止续约的持有者，在 TTL 之后被接管。这段时间由观察者自己的单调时钟计量，从它第一次看到当前记录的那一刻起算。
- `runFenced` 持有仓储的按键围栏，并在工作开始前重新读取记录。等待围栏会在租约丢失时停止。工作的 fiber 结束时释放围栏，因此后继者的围栏工作在那之后才开始。被中断的 fiber 立刻结束，但它启动的 Promise 继续运行。无法取消的写入放进 `Effect.uninterruptible`（围栏会等它落定），或者把 `Effect.tryPromise` 提供的 AbortSignal 传给它，让它只在写入停止后才落定。
- 只有当每个写入者都经过同一台机器上的同一个仓储时，守卫加重新读取才和受保护资源自己做的检查一样强。能够原子比较的资源应当保留它见过的最高令牌，并拒绝更小的代次。
- `sqliteLeaseRepository` 在 `BEGIN IMMEDIATE` 事务里比较修订。`fileLeaseRepository` 是没有 SQLite 时的回退：每个键一个 JSON 文件，在按键的锁文件下写入。`memoryLeaseRepository` 服务一个进程。
- 仓储端口遵循工具包的仓储形状。`load(key)` 是已存储的 `LeaseSnapshot` 或 `undefined`。`save(key, snapshot, expectedRevision)` 只覆盖那个修订，另一个写入者先移动了记录时以 `RevisionConflict` 失败。

预期失败是带 `_tag` 的类型化值：`LeaseHeld`、`LeaseLost`、`LeaseConfigInvalid`、`LeaseRepositoryFailure`，以及仓储的 `RevisionConflict`。工具包自己不运行 Effect。请在应用的组装根上运行这个程序。

持有者按主机名、boot id、pid 和启动时间判断。win32、NFS、容器和被改名的主机见 [安装](/zh/docs/installation)。
