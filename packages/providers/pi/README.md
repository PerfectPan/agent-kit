# Pi provider

Private implementation of Pi identity, discovery, hooks, installation, sessions and usage, bundled into `@rivus/agent-kit`. Each service has its own export; `facts.ts` owns Pi configuration and `layout.ts` owns its session storage layout. Context imports use SPI entries, and tests run the shared hook, discovery, usage and session conformance checks. Pi has no ACP profile.

## Sessions (pi-coding-agent 0.87.1, session format v3)

Verified against the installed `@earendil-works/pi-coding-agent` 0.87.1 (`dist/core/session-manager.js`, `docs/session-format.md`, `docs/message-types.md`, `@earendil-works/pi-ai` `dist/types.d.ts`) and the session files under `~/.pi/agent/sessions`.

- Recorded: requests with usage and finish reasons, reasoning parts, compaction entries (`tokensBefore` as `preTokens`, the summary) with `compactionTokens`, and the system prompt and tool schemas (`systemPrompt`, `toolSchemas`).
- The system prompt and the tools ride `message` entries with `role: "system"`, as deltas that `getCurrentSystemMessage` / `getCurrentTools` replay: the leading one declares `sections` (named, ordered; `null` removes one), later ones append `content`, replace sections by name and add or remove tools (`toolsAdded`, `toolsRemoved`). Each becomes a `prompt_snapshot` system event whose `systemPrompt` is `getSystemMessageText`'s rendering (the content texts and the surviving sections joined by blank lines) and whose `tools` are the declarations `{name, description, parameters}` in insertion order. A compaction entry's `systemMessage` is the complete checkpoint Pi continues from, so the replay restarts from it as the compaction's second event. A transcript lists `systemPrompt` and `toolSchemas` only when a snapshot or the session records them.
- Not recorded, so never listed: turn durations (a message carries the `timestamp` of its stream start only; `dist/core/timings.js` is startup profiling behind `PI_TIMING=1`), subagents (none of the entry types in `docs/session-format.md` and no such field in `dist` or `@earendil-works/pi-ai`) and hooks (no hook entry; `fromHook` only marks a `custom_message` or a compaction as written by an extension). `docs/message-types.md` describes a `replace` flag on system messages that 0.87.1 neither types nor replays; the adapter ignores it.
- Pi counts `usage` entries (model calls that are no assistant message, such as cache warming) and a compaction's `usage` (the summary call) toward its own session totals; the usage decoder and the transcript read assistant messages only, so they leave both out.
