# Codex provider

Private implementation of Codex identity, discovery, hooks, installation, sessions, usage and ACP, bundled into `@rivus/agent-kit`. Each service has its own export; `facts.ts` owns configuration facts, `layout.ts` owns active and archived rollout paths, and `records/` shares parsing, usage and fork replay between the session and usage readers. Context imports use SPI entries. Tests run the hook, discovery, usage and session conformance suites; cross-agent detection and hook samples also run against the complete tables in testing.

Sessions read one rollout per session. `session_meta.base_instructions.text` is the session's system prompt. The `additional_tools` items Codex writes when it adds tools to the thread become `prompt_snapshot` events whose `tools` stay verbatim, and the main lane's latest snapshot is the session's `tools`. The `hook_started`/`hook_completed` events of configured hooks become `hook` events carrying the run's hook event name (upstream persists them through `send_event`, so rollouts record only the hooks that ran). A `compacted` record snapshots the latest reachable token usage, whose `input_tokens` is the compaction's pre-compaction token count; no record names the context after the compaction, so there is no post-compaction count.
